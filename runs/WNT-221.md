## Implemented rules

[search-and-grouping.md](../docs/search-and-grouping.md) and initial grouping/search
tests were written **before implementation**. The [test-first transcript](WNT-221-test-before.txt)
records the expected compilation failure for the missing projection API.

The pure projection uses exact host plus Jaccard similarity of normalized title
keyword sets, threshold >= 0.5, against a fixed newest-item representative. Best
score wins, ties use representative capture descending then ID descending. Null,
blank and tokenless titles have a separate host fallback. Groups and contents
sort by capture/ID recency. Archived partitions by local capture calendar day
before applying similarity. Normalization, non-transitive behavior and language
limitations are explicit in the policy; no invented topic labels or manual tags.

Search scans title, description, original URL and canonical URL as literal
normalized substrings, with explicit Inbox / Archived / All scopes. All excludes
soft-deleted items. A blank query lists its scope; punctuation is literal.
Room emits changes to a ViewModel projection on Dispatchers.Default, so capture,
metadata and lifecycle updates affect search/grouping without a persisted index.
SQLite FTS was evaluated and deferred for these substring semantics and MVP size.
No schema, dependency, preview transport, capture or lifecycle-write change.

within a host/day. Large-collection performance is not benchmarked. The heuristic
does not translate or segment all scripts, and removing combining marks can fold
distinctions in some languages. Controls survive activity recreation; search
query/scope restoration after process death is not claimed. Persisted links and
lifecycle state are verified after restart. Group membership can change with new
metadata, captures, re-shares or lifecycle transitions, as documented.

API 23/36 device runtimes, TalkBack/large-font/RTL, release signing and store
