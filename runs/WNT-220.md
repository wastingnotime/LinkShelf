## Policy and limits

The full policy is in [apps/mobile/README.md](../apps/mobile/README.md#preview-enrichment).
HTTP(S) only, credentials rejected, static conservative public-address policy,
every DNS answer/redirect validated, addresses pinned through connection,
no proxy/cookies/auth/Referer/automatic redirects/connection reuse/HTTP2.
Default TLS certificate and hostname verification is retained. HTTP links use
explicit cleartext support through this same transport.

Maximum three redirects per resource, 512 KiB HTML, 2 MiB image, 3-second DNS wait,
5-second connect/read and 15-second total call timeout per hop. At most eight calls
per attempt (page and image, up to four hops each). Compressed responses are
rejected. Rejected/redirect bodies are cancelled before close so OkHttp cannot
silently drain them beyond the application byte cap. Images are JPEG/PNG/WebP,
maximum 4,096 per side / 8 million source pixels, sampled to at most 1,024 per side
and saved as app-private JPEG. The UI never loads remote image URLs.

Four total attempts for I/O, DNS, timeout, 408/429/5xx failures; exponential backoff
starts at 30 seconds. Image retries retain text; terminal failure retains useful
previous metadata if available. Unsafe/permanent failures settle immediately.
Failed cards can retry manually or by re-sharing. Room's pending state recovers
any gap before WorkManager persistence on next app launch. Work chains serialize
per-ID retries, and ready/deleted rows skip fetching. Android controls exact
execution timing; force-stop requires relaunch. Soft-deleted records/thumbnails
are retained, consistent with the existing no-purge policy.

## Limits, blockers and delivery

No implementation blocker remains. No real Chrome/YouTube/WhatsApp Sharesheet,
physical phone, reboot, API 23/36 device runtime, TalkBack/large-font/RTL, release
signing or store delivery validation is claimed. The smoke uses real ACTION_SEND
through ActivityManager and public HTTPS OG metadata/images; Twitter, adversarial
redirects, malformed metadata and transient recovery are deterministic tests.
External website behavior is not guaranteed. Compressed, blocked, private,
script-only and unsupported-format pages/images deliberately fall back; public
special-purpose network exceptions are conservatively blocked. Static IP policy
needs maintenance as IANA allocations change. The underlying platform DNS call
may ignore interruption, but caller waits, thread count and queue are bounded.

Search/grouping remain milestone 3. WNT-220 changes neither that scope nor the
accepted opening/archiving, deduplication or soft-delete policies. This work is for
review only: do not merge or complete the Linear issue from this execution.
